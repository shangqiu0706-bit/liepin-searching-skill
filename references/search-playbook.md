# 搜索 Playbook

## 搜索矩阵模板

在 `search-log.md` 用表格记录：

| 搜索轴 | 查询词/公司 | 从当前 JD 推导的依据 | 搜索页筛选及理由 | 目的 | 结果数 | 已查看页数 | 新公司 | 新候选人 | 详情页最终判定字段 | 状态 |
|---|---|---|---|---|---:|---:|---|---|---|---|

每个岗位先重建以下搜索轴，具体名称和顺序由 JD 决定：

1. 当前 JD 的核心职责、工作对象和业务结果。
2. 当前岗位实际使用或协作的渠道、系统、工具、方法和专业术语。
3. 当前产品/客户/人群/业务模式对应的同类及可迁移场景。
4. 根据当前岗位画像生成的公司集合和公司类型。
5. 从高相关候选人履历中发现公司，再用当前岗位的等价职能和结果词做公司反查。
6. 只有在相似性判断成立时，才引用其他岗位的搜索资产；否则只借鉴“候选人反查公司”等方法逻辑，不复用具体公司和关键词。

如果 JD 的关键词或公司范围不足以形成有效区分，向用户询问参考关键词/公司；用户补充内容先标记为本案输入，除非用户明确要求沉淀，否则不写入通用规则。

## 候选人证据卡

每个进入核验的人在日志里保留一行或一小段：

```text
候选人：展示名 / 简历ID
来源：查询词或公司反查
城市：当前城市；期望城市
薪资（详情页）：原文；月薪下沿-上沿 × 薪次数；固定薪 / 提成 / 总包备注；与岗位薪资区间的交集；预算判定
搜索页筛选：使用了什么；是否可能造成遗漏
证据：与JD最相关的公司、岗位、平台、业务结果
判断：推荐 / 可沟通边界 / 待验证 / 剔除 + 原因与待核验项
链接：详情页URL
```

只摘录必要证据，不复制整份简历。简历 ID 仅用于本案去重和复核，不作为公开输出的替代姓名。

## 何时停止一条搜索线

一条查询线可以停止的条件是：已查看当前可见结果中的相关候选、连续页面主要重复或明显不相关、并且新公司队列已经转入反查；不要因为第一页没有合适人选就停止。若用户说“继续搜”“还没搜完”，优先翻页和清空过窄关键词，再做公司反查。

## 结果输出建议

- 先给判断：推荐池数量、最值得优先看的 3–5 人和主要缺口。
- 推荐池按“匹配度/城市/薪资风险”排序；薪资区间有实际交集即可保留，不要求候选人报价完全落入岗位区间。
- 可沟通边界池保留薪资仅卡线、迁移确认或一项明确风险的人；待验证池保留公司/职位信号强但业务证据不足的人。完全无薪资交集或明显不相关的人只在剔除摘要中出现。
- 若用户要 Excel，使用可筛选表格，年化下沿/上沿保留为数值列，薪资校验用公式或明确可追溯的字段。
